# 指数全字段补齐与逐值核验

## 目标与边界

用户要求覆盖「指数」内全部标的、PB 等全部字段，逐项校验已有数值，修复有证据的错误，明确标注存疑与无法核实项，并逐标的交付补齐及修正汇总。基线为 2026-11-16 的 521 个 active INDEX，不能把现有接口覆盖当作完整范围。

- 参考页仅帮助核对字段和定义，不复制第三方行情；优先发行方和交易所官方数据。
- 所有字段均须有数值及来源证据，或有逐字段核实的缺失 / 不适用 / 存疑状态和原因；不能用「未接入」作为停止可行数据补齐的依据。
- 不猜测、插值、补零、借用其他指数；不同口径分开保存，不把新源混入已有历史。
- 真实库写入前备份，使用幂等、可审阅的计划和事务；保留原值、来源原文摘要及修正依据。
- 不触及交易流水、AI 密钥或真实 DSH 安装。用户后续明确授权「更新版本推送 GitHub」，本次以 0.1.5 提交并推送 main；发布不等于本数据完整性 Goal 完成。

## 验收清单

1. 全范围：从当前库和指数列表列定义列出完整标的 × 字段矩阵，包含发布日期、最新点位、YTD、场内 / 场外基金数、PE/PB/PS 八项统计、三年 ROE、股息率、市值及其元数据；其他指数视图使用同一核验后的基础数据。
2. 来源扩展：核实中证与国证官方公开页面、端点、表头和方法，逐字段确认身份、日期、单位、适用范围与缺失含义；修复东财遗漏 INDEX 的调用路径。优先解决 PB 缺口及可取得的同源历史。
3. 完整性：全标的逐源取证、记录成功 / 空数组 / 未覆盖 / 失败；有证据的数据落库并在正常刷新中持续更新，不能只有一次性脚本。
4. 正确性：全量存储数据结构、日期、重复、数值范围和来源校验；同日同定义数值对照，跨口径保持不可比；派生值独立重算，异常状态在 API、UI、导出一致。
5. 验证：解析 fixture、调用参数、缺失/空白/无效/重复/未来数据/冲突、失败不覆盖既有值和重复执行幂等；npm test、npm run check、真实 Chrome verify:web、HTTP smoke、打包安装契约通过。
6. 交付：逐标的字段状态、补齐前后差异、问题及修正证据 JSON/CSV；说明覆盖、规则、仍不可核实项和实际限制；README/AGENTS 按稳定事实同步，ROADMAP 记录当前状态。
